# H-01~H-10 사용자 사고 시나리오 추적표

| 항목·화면/정상 흐름 | 대표 Worst Case·원인 | 서버 감지·방어 | UI·DB/state·다음 단계·테스트/TBD |
|---|---|---|---|
| H-01 첫 로그인 | 여러 기기 동시 첫 로그인 | `(user,check_in_date)` unique와 서버 날짜 | 하나의 출석 결과만 표시 |
| H-02 연속 출석 | 날짜/시간대 오판 | 서버 정책 timezone 기준 날짜 비교 | streak 표시; timezone 정책과 일치 |
| H-03 연속 끊김 | 장기 미접속/경계 날짜 | 이전 출석일 비교 | 새 streak 표시; 소급 정책 `TBD` |
| H-04 같은 날 재로그인 | 응답 유실 뒤 중복 처리 | 기존 날짜 row 반환 | 신규 보상 애니메이션 반복 금지 |
| H-05 동시 실행 | 둘 다 사전 SELECT에서 없음 | DB unique/insert conflict 처리 | 같은 확정 결과 반환 |
| H-06 없는 사용자 | 오래된/위조 token | 인증 subject와 USERS 확인 | 401/404 계약, 출석 row 없음 |
| H-07 보상 | 출석 사실과 보상 write 분리 | 출석 event 식별자와 재화 원자 증가 | 최신 balance; 보상 수치는 승인 근거만 사용 |
| H-08 실패 rollback | 기록 성공 후 보상 실패 | 같은 짧은 transaction 또는 명시적 복구 상태 | 부분 성공 숨기지 않음; 재실행 멱등 |
| H-09 조회 | 큰 이력/다른 user 조회 | owner·pagination 상한 | 본인 이력만 표시 |
| H-10 자정 경계 | 23:59 로그인, 00:01 완료 | 서버가 정의한 check-in 판정 시각 | 귀속 날짜 명시; 판정 기준 `TBD`이면 확정 금지 |

일일 미션과 출석은 별개다. 현재 ERD의 `ATTENDANCES.daily_quest_completed`는 오늘 미션의 완료 상태만 나타내며, 출석 보상 지급 여부나 문제별 보상 지급 이력을 대신하지 않는다.
