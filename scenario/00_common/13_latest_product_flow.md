# 최신 전체 서비스 흐름 기준

이 문서는 현재 시나리오 설계의 **최상위 제품 흐름 기준**이다.

아래 흐름과 충돌하는 오래된 문구가 있으면 이 문서를 우선 기준으로 보고 해당 문서를 수정한다.

---

# 1. 핵심 흐름

```text
로그인
  ├─ 그날 첫 로그인 → 자동 출석 1회 → 100원 지급
  └─ 이미 오늘 출석 → 추가 지급 없이 정상 로그인
  ↓
 홈
  ├─ 학습 → 문제 선택 → 코드 작성 → 제출 → 채점 → 정답 보상
  ├─ 배틀 → 방 참가 → Ready → 게임 시작 → 문제 풀이 → 점수 경쟁 → 배틀 결과 보상
  ├─ 랭킹/승급전 → 랭킹 확인 → 승급전 도전 → 문제 풀이 → 성공/실패
  │                                         ├─ 성공 → 승급 성공 보상
  │                                         └─ 실패 → 종료
  │
  └─ 상점 / 가챠 / 하우징으로 직접 이동 가능

정답 보상 / 배틀 결과 보상 / 승급 성공 보상 / 출석 보상
  ↓
재화
  ├─ 상점 → 가구 구매 → 하우징 적용
  └─ 가챠 → 고양이 획득 → 하우징에서 확인/배치

하우징
  ├─ 가구 배치
  └─ 고양이 상호작용
```

---

# 2. 생산 루프와 소비 루프

## 생산 루프

```text
학습
배틀
승급전 성공
출석
→ 재화 증가
```

학습 실패, 배틀 패배, 승급전 실패가 어떤 보상을 받는지는 별도 비즈니스 규칙으로 확정한다.

## 소비 루프

```text
재화
→ 상점
→ 가구
→ 하우징
```

```text
재화
→ 가챠
→ 고양이
→ 하우징
```

상점/가챠 화면 접근 자체는 재화 보유 여부와 무관하게 가능하다. 재화가 부족하면 실제 구매/뽑기 요청만 실패한다.

---

# 3. 출석은 확정된 로그인 사이드 플로우

출석은 별도 메인 메뉴를 눌러야 발생하는 기능이 아니다.

확정 요구사항:

```text
매일 자정 이후 첫 로그인
→ 자동 출석 처리
→ 100원 지급
```

따라서 최종 구현은 로그인 성공 흐름에서 출석 서비스를 실행하는 구조를 기준으로 한다.

같은 날 재로그인하면:

```text
로그인 성공
→ 오늘 출석 이미 존재
→ 추가 출석/추가 100원 없음
→ 정상 홈 진입
```

이어야 한다.

현재 존재하는 수동 check-in API는 구현 단계에서 공통 attendance service를 재사용하는 방식으로 정리한다.

서비스 기준 timezone은 아직 팀 확정 대상이며 클라이언트 날짜는 신뢰하지 않는다.

---

# 4. 대표 흐름도에 없어도 유지하는 기능

상위 흐름도에 모든 세부 행동을 넣지는 않는다.

다음 기능은 상세 시나리오에서 계속 유지한다.

- 회원가입/인증
- 방 생성
- ROOM_TASKS 설정
- 재접속
- 오류/rollback
- 관리자/master data
- 출석 이력 조회
- 고양이 기억/대화

상위 흐름도에 안 보인다는 이유로 해당 기능이 자동으로 MVP 제외되는 것은 아니다.

# 5. 도메인 책임 연결

- 학습: `01_learning_grading/`
- 가챠/고양이: `02_gacha/`
- 배틀: `03_battle/`
- 랭킹/승급전: `04_rank_challenge/`
- 로그인/회원가입/JWT: `05_auth/`
- 하우징: `06_housing/`
- 상점/Inventory: `07_shop/`
- 출석: `08_attendance/`

도메인이 나뉘어 있어도 사용자 경험은 다음 한 루프로 이어진다.

```text
활동
→ 결과 확정
→ 보상/재화
→ 소비
→ 하우징/고양이로 결과 확인
```

---

# 6. 문서 해석 원칙

1. 확정 요구사항과 추천안을 구분한다.
2. 가격·확률·점수·제한시간 등 미정 숫자는 이 흐름에서 새로 만들지 않는다.
3. 프론트 화면의 mock 값은 별도 확정이 없는 한 비즈니스 규칙으로 취급하지 않는다.
4. 재화 구조가 변경되면 학습·출석·배틀·승급전·상점·가챠 문서를 함께 갱신한다.
5. 인증이 붙으면 사용자 자산 write는 JWT/current_user를 기준으로 전환한다.

이 문서가 현재 제품 흐름의 상위 기준이다.
