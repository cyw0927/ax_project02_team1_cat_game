# 02. 상품 선택 및 구매 전 확인

## 목적
사용자가 실제로 어떤 아이템을 살지 선택하고, 구매 직전 필요한 정보와 제한 조건을 확인하는 단계다.

## 정상 흐름
1. 사용자가 상품 카드를 선택한다.
2. 클라이언트가 상품 상세와 현재 보유 수량을 표시한다.
3. 구매 버튼을 누르기 전 서버 기준 item_id를 유지한다.
4. 실제 가격과 구매 가능 여부는 다음 구매 요청 단계에서 다시 확인한다.

## 발생 가능한 변수
### A. 상품 상세를 연 뒤 아이템이 변경/삭제됨
- 오래 열린 화면에서는 충분히 발생할 수 있다.
- 해결: 구매 요청 시 item 존재 여부를 다시 확인한다.
- UI: `현재 구매할 수 없는 상품입니다.`

### B. 이미 보유한 상품
- 수량형 가구라면 재구매가 정상일 수 있다.
- 단일성 상품인지 여부는 현재 정책이 확정되지 않았으므로 임의 제한하지 않는다.

### C. wallpaper/floor 계열
- 여러 개 보유와 실제 적용은 다른 개념이다.
- 구매 가능 여부와 현재 적용 상태를 혼동하지 않는다.

### D. 최대 보유량 도달
- 최대 수량 정책은 현재 `TBD`.
- 존재하지 않는 제한을 프론트에서 임의로 만들지 않는다.

### E. 가격이 UI와 서버에서 다름
- 화면 렌더 이후 가격이 변경될 수 있다.
- 구매 확정은 서버 최신 가격 기준.

### F. 클라이언트가 가격을 조작
- 서버는 클라이언트 price를 신뢰하지 않는다.
- item_id를 기준으로 DB에서 가격을 조회한다.

## UI
- 이름/카테고리/가격
- 현재 보유 수량
- 적용중 여부가 있다면 별도 표시
- 구매 버튼
- 구매 불가 사유가 서버에서 명확한 경우 해당 사유 표시

## DB/API 영향
이 단계 자체는 원칙적으로 읽기 단계다. 구매 확정 전 balance/inventory를 임의 변경하지 않는다.
