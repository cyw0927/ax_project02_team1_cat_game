# 08. 하우징 연결

## 목적
상점에서 구매한 가구/벽지/바닥 등 하우징 관련 아이템을 실제 하우징에서 사용할 수 있도록 최신 인벤토리 상태를 전달한다.

## 정상 흐름
1. 구매가 성공하고 inventory가 반영된다.
2. 사용자가 `하우징에서 배치` 또는 하우징 메뉴로 이동한다.
3. 하우징 진입 시 서버에서 최신 INVENTORIES와 현재 배치 상태를 조회한다.
4. 구매한 아이템이 사용 가능 목록에 표시된다.
5. 사용자가 배치/적용한다.
6. 배치 결과는 하우징 도메인의 저장 규칙에 따라 별도 처리한다.

## 발생 가능한 변수

### A. 구매 성공 직후 하우징에 아이템이 안 보임
- 원인: 하우징 화면이 이전 inventory를 캐시하고 있음.
- 해결: 하우징 진입 또는 구매 완료 후 inventory 재조회.
- UI: 임의 로컬 추가보다 서버 최신 목록을 기준으로 갱신.

### B. 다른 기기에서 이미 해당 아이템을 사용/변경
- 원인: 다중 기기 사용.
- 해결: 하우징이 서버 최신 inventory와 PLACED_OBJECTS를 권위 상태로 사용.

### C. 보유 수량보다 많이 배치하려 함
- 원인: 오래된 화면, 동시 편집, 배치 로직 오류.
- 해결: 서버에서 실제 보유 수량과 현재 배치 수를 검증한다.
- 정확한 `배치 중인 아이템도 inventory quantity에서 차감하는지`는 하우징 정책과 일치시켜야 하며 미확정이면 `TBD`.

### D. 벽지/바닥처럼 수량형 가구와 성격이 다른 아이템
- USERS.wallpaper_item_id / floor_item_id와 연결되는 항목은 일반 PLACED_OBJECTS와 다른 적용 경로를 가질 수 있다.
- UI와 API는 category에 따라 적절한 적용 방식을 사용한다.

### E. 상점에서 구매 가능한데 하우징에서는 지원되지 않는 category
- 원인: 신규 아이템 category 추가 후 하우징 구현 누락.
- 해결: 상품 노출 전에 실제 사용 가능 category를 검증하거나 `아직 배치할 수 없는 아이템`으로 명확히 표시.

### F. 하우징 저장 실패
- 구매 자체는 이미 성공한 별도 거래다.
- 배치 저장 실패 시 구매를 rollback하지 않는다.
- 사용자는 아이템을 여전히 보유하며 배치만 재시도한다.

## 경계 원칙
`상점 구매`와 `하우징 배치`는 서로 다른 트랜잭션이다.

- 상점: 재화 차감 + inventory 획득
- 하우징: 보유 아이템 검증 + 배치/벽지/바닥 상태 변경

하우징 저장 실패 때문에 이미 완료된 구매 transaction을 되돌리지 않는다.

## UI
- 구매 완료 화면에서 `하우징에서 사용하기` 버튼 가능.
- 하우징 진입 시 새 아이템 표시/강조 가능.
- 서버에 없는 아이템을 프론트만 임의 추가하지 않는다.

## DB/API 영향
- INVENTORIES 최신 조회
- PLACED_OBJECTS 배치 저장
- USERS.wallpaper_item_id / floor_item_id 적용
- 자세한 배치 규칙은 `scenario/by_flow/07_housing/` 흐름을 따른다.

## 다음 흐름
`재화 획득 → 상점 → 구매 → inventory → 하우징 → 배치/적용`

이 단계에서 상점 흐름은 종료되고 하우징 흐름으로 책임이 넘어간다.

## 테스트
- 가구 구매 후 즉시 하우징 이동
- 기존 하우징 탭이 열린 상태에서 구매
- 여러 기기 동시 사용
- 보유 수량 초과 배치 시도
- 벽지 구매/적용
- 바닥 구매/적용
- 지원되지 않는 category
- 하우징 저장 실패 후 아이템 보유 유지
