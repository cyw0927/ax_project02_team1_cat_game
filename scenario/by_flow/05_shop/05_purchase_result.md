# 05. 구매 완료 응답 및 최신 상태 반영

## 목적
DB 거래가 정상 commit된 뒤 사용자가 실제로 무엇을 샀는지, 잔액과 보유 수량이 어떻게 바뀌었는지를 서버 최신 상태로 확정한다.

## 정상 흐름
1. 구매 transaction commit 성공.
2. 서버가 최신 balance와 해당 item의 inventory quantity를 확정한다.
3. 성공 응답에 구매 item과 최신 상태를 포함한다.
4. 클라이언트는 응답값으로 잔액/보유 수량을 갱신한다.
5. 필요하면 `하우징에서 배치` 동선을 제공한다.

## 발생 가능한 변수
### A. commit은 성공했지만 HTTP 응답 유실
- 원인: 네트워크 끊김, 브라우저 종료.
- 위험: 사용자는 실패로 생각하고 다시 구매할 수 있다.
- 해결: 재접속 시 서버 balance/inventory를 재조회한다. 구매 idempotency가 없다면 재구매 버튼을 바로 반복하기보다 `구매 상태 확인` 흐름을 제공하는 것이 안전하다.

### B. 오래된 응답이 최신 상태를 덮어씀
- 여러 요청이 동시에 있으면 응답 순서가 역전될 수 있다.
- 중요한 거래 후에는 해당 거래 응답 또는 최신 서버 재조회 결과를 기준으로 화면을 갱신한다.

### C. 다른 기기에서 동시에 구매/사용
- 현재 화면의 quantity가 곧바로 낡을 수 있다.
- 다음 거래나 하우징 진입 시 서버 최신 상태를 다시 읽는다.

### D. UI 애니메이션 중 실제 상태 조회 실패
- 연출과 서버 상태를 분리한다.
- 애니메이션이 성공했다고 DB 상태까지 성공한 것으로 간주하지 않는다.

## UI
- 구매 성공 메시지
- 구매한 아이템
- 최신 잔액
- 최신 보유 수량
- `하우징으로 가기` 또는 `계속 쇼핑` 동선

## DB/API 영향
이 단계에서 별도 재차감/재지급을 하지 않는다. commit된 거래 결과를 읽고 전달한다.
