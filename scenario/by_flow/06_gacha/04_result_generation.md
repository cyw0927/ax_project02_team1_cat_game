# 가챠 4단계 — 결과 생성

## 목적
가챠 결과를 서버 권위 상태로 한 번만 생성하고, 같은 거래가 재시도돼도 결과가 바뀌지 않게 한다.

## 정상 흐름
1. 서버가 현재 활성 가챠 풀과 확률 설정을 읽는다.
2. 유효한 후보 고양이만 대상으로 결과를 생성한다.
3. 생성된 결과를 거래 식별자와 연결해 영속화한다.
4. 이후 같은 거래 재조회 시 저장된 동일 결과를 반환한다.

## 중요한 원칙
- 실제 보상 `cat_id`는 클라이언트 `Math.random()`으로 결정하지 않는다.
- 확률표, 픽업, 천장, 보정 확률은 서버/운영 정책에서 관리해야 한다.
- 현재 확정되지 않은 수치는 모두 `TBD`로 유지한다.

## 발생 가능한 변수
### A. 확률 합계가 비정상
- 원인: 운영 설정 오류.
- 감지: 풀 로딩 시 합계 검증.
- 처리: 잘못된 확률표로 뽑기를 실행하지 않고 운영 오류로 중단한다.

### B. 특정 rarity에 후보 고양이가 없음
- 원인: 비활성화/삭제, 잘못된 풀 설정.
- 처리: 해당 rarity가 선택된 뒤 임의 fallback 고양이를 주지 않는다. 풀 자체를 유효성 검증하고 가챠를 막는다.

### C. 이미 비활성화된 고양이가 풀에 남음
- 처리: 결과 생성 전에 활성 여부를 검증한다.

### D. 서버 재시도 시 랜덤이 다시 굴러감
- 위험: 같은 결제에서 서로 다른 결과가 생김.
- 해결: 거래 식별자를 기준으로 최초 생성 결과를 저장하고 재시도 시 기존 결과를 반환한다.

### E. 랜덤 생성 후 저장 실패
- 위험: 서버는 결과를 만들었지만 복구할 근거가 없음.
- 해결: 결과 생성과 저장 순서를 명확히 설계한다. 전용 가챠 이력 테이블 여부는 `TBD`.

## UI
