# 08. 재화 반영 및 랭킹 재조회

## 목적
승급 성공 보상과 랭킹 변경을 최신 서버 상태로 확정하고, 사용자가 이후 상점/가챠/하우징/홈으로 이동할 때 오래된 화면 값을 사용하지 않도록 한다.

## 정상 흐름
1. 승급 성공 처리와 보상 transaction이 끝난다.
2. 서버에서 최신 랭킹 참가자 상태와 재화 잔액을 읽는다.
3. 클라이언트는 성공 응답 또는 재조회 결과로 화면을 갱신한다.
4. 사용자는 랭킹 화면으로 돌아가거나 다른 기능으로 이동한다.

## 발생 가능한 변수
### A. 승급 성공은 확정됐지만 랭킹 화면이 오래됨
- 해결: 로컬에서 순위를 `+1`하지 않고 서버의 최신 목록을 재조회한다.

### B. 보상 commit 후 응답 유실
- 해결: 재접속 시 challenge.status, 랭킹 상태, 서버 balance를 다시 읽는다. 보상은 멱등성으로 중복 지급하지 않는다.

### C. 다른 기능에서 동시에 balance 변화
- 예: 승급 보상과 학습/배틀 보상이 동시에 들어옴.
- 해결: DB 원자 증가로 lost update를 방지하고 서버 최신 잔액을 표시한다.

### D. 다른 기기에서 상점/가챠 사용
- 해결: 다음 거래는 항상 서버가 최신 잔액으로 검증한다. 현재 화면 숫자는 권위 상태가 아니다.

### E. 실패/TIMEOUT 사용자가 이 단계로 진입
- 해결: challenge.status를 확인하고 성공 보상 흐름으로 보내지 않는다. 실패/TIMEOUT은 결과 화면에서 종료하거나 재도전 정책을 안내한다.

### F. 재도전 가능 시점 미확정
- cooldown/횟수 제한은 `TBD`. 화면에 임의 카운트다운을 만들지 않는다.

## 다음 흐름
- 랭킹 재확인: 최신 group/participant 목록 재조회
- 홈: 완료 상태만 표시
- 상점: 최신 balance + 서버 가격 검증
- 가챠: 최신 재화 + 서버 정책 검증
- 하우징: 승급 보상 자체가 직접 배치를 바꾸는 것은 아니며 이후 획득 아이템/고양이가 반영됨

## 장애 문의 시 추적 정보

4. challenge.status

8. 보상 지급 여부
9. 현재 rank score
10. 현재 서버 balance
