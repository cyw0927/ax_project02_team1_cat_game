# 06. 성공 / 실패 / TIMEOUT 판정

## 목적
승급전 결과를 단 한 번의 종료 상태로 확정하고 이후 결과가 뒤집히지 않도록 한다.

## 정상 흐름
1. 서버가 현재 challenge 상태를 확인한다.
2. 이미 종료 상태라면 기존 결과를 그대로 반환한다.
3. 아직 IN_PROGRESS라면 서버 현재 시각과 문제 통과 상태를 확인한다.
4. 확정된 합격 기준에 따라 SUCCESS 또는 FAILED를 판정한다.
5. 제한 시간 정책에 따라 TIMEOUT 여부를 함께 판단한다.
6. IN_PROGRESS에서 하나의 종료 상태로 전이한다.

## 발생 가능한 변수
### A. SUCCESS와 TIMEOUT 판정이 동시에 발생
- 원인: 마지막 채점 완료와 만료 처리 작업이 경쟁.
- 위험: 결과가 두 번 바뀌거나 서로 다른 응답이 나갈 수 있음.
- 해결: `IN_PROGRESS → SUCCESS/FAILED/TIMEOUT` 중 하나만 성공하도록 조건부 UPDATE 또는 필요한 경우 짧은 row lock을 사용한다.

### B. 결과 판정 함수 재실행
- 원인: 새로고침, retry, background 재실행.
- 해결: 종료 상태는 멱등하게 반환하고 재판정으로 결과를 바꾸지 않는다.

### C. 합격 기준 미확정
- 후보: 전 문제 통과, 일정 개수 이상 통과, 점수/시간 기준.
- 정책: 최종 기준은 `TBD`. 문서에서 임의 확정 금지.

### D. 제한 시간 기준 미확정
- 제출 수락 시각/채점 완료 시각 중 무엇을 기준으로 할지 `TBD`.

### E. 일부 채점이 시스템 오류 상태
- 해결: 시스템 오류를 사용자 실패로 자동 확정하지 않는다. 재시도 가능 여부와 종료 정책을 별도 결정한다.

## DB/상태 원칙
- 종료 상태가 확정된 뒤 다시 IN_PROGRESS로 돌아가지 않는다.
- 상태 전이는 짧게 처리한다.
- Docker 채점 실행 중 challenge row lock을 유지하지 않는다.

## UI
- SUCCESS: 승급 성공 화면
- FAILED: 실패 화면 및 통과 현황
- TIMEOUT: 시간 종료 안내
- 판정 대기: 아직 시스템 채점이 남았다면 별도 상태 표시 가능
