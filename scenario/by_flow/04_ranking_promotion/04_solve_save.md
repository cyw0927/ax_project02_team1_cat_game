# 04. 문제 풀이 및 중간 저장

## 목적
승급전 진행 중 사용자가 코드를 작성하고, 새로고침이나 네트워크 문제 이후에도 가능한 범위에서 작업을 복구할 수 있게 한다.

## 정상 흐름
1. 서버가 challenge 상태가 IN_PROGRESS인지 확인한다.
2. 서버 현재 시각이 expires_at 이전인지 확인한다.
3. 현재 task_order의 문제를 표시한다.
4. 사용자가 코드를 작성한다.
5. 필요 시 saved_code에 중간 저장한다.
6. 다음 문제 이동 또는 최종 제출 전 최신 저장 상태를 유지한다.

## 발생 가능한 변수
### A. 브라우저 새로고침
- 해결: 서버의 saved_code를 다시 불러와 복원한다.

### B. 저장 중 네트워크 끊김
- 위험: 사용자는 저장된 줄 알지만 서버에는 반영 안 됨.
- 해결: 저장 성공 응답을 받은 버전까지만 권위 상태로 본다. UI에 저장 상태 표시 가능.

### C. 오래된 저장 응답이 최신 코드 덮어쓰기
- 원인: 여러 저장 요청의 응답 순서 역전.
- 해결: 저장 버전/updated_at 도입을 검토. 확정되지 않았다면 `TBD`로 둔다.

### D. challenge가 이미 SUCCESS/FAILED/TIMEOUT
- 해결: 저장을 거절하고 최신 종료 상태를 반환한다.

### E. 제한 시간 종료 직전 저장
- 서버 현재 시각을 기준으로 허용 여부 판단. 클라이언트 타이머만 믿지 않는다.

### F. 이미 통과한 문제 수정
- 재수정 허용 여부는 정책 `TBD`. 결과 상태를 되돌리는 구현은 임의로 만들지 않는다.
