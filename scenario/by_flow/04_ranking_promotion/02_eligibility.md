# 02. 승급전 도전 가능 여부 확인

## 목적
새 승급전을 시작해도 되는지 서버가 최종 판정하는 단계다.

## 정상 흐름
1. 사용자가 `승급전 도전` 클릭.
2. 서버가 최신 랭킹 그룹/점수/기존 challenge 상태를 다시 조회한다.
3. 진행 중 challenge가 없는지 확인한다.
4. 확정된 도전 조건을 모두 만족하면 생성 단계로 이동한다.
5. 불가하면 사유를 반환한다.

## 발생 가능한 변수
### A. 이미 IN_PROGRESS challenge 존재
- 원인: 이전 도전을 끝내지 않음, 다른 기기에서 이미 시작.
- 해결: 새 challenge를 만들지 않고 기존 challenge를 이어가게 한다.

### B. TIMEOUT 시간이 지났지만 상태가 IN_PROGRESS
- 원인: 만료 정리 작업 미실행, 사용자가 오래 접속하지 않음.
- 감지: 서버 현재 시각과 `expires_at` 비교.
- 해결: 만료 상태를 정리한 뒤 도전 가능 여부를 다시 판단한다.

### C. 두 탭에서 동시에 도전 클릭
- 위험: challenge가 2개 생성될 수 있음.
- 해결: `활성 challenge 1개` 규칙이 확정이라면 DB UNIQUE/조건부 상태 처리/짧은 락 등으로 서버에서 보장한다. 버튼 비활성화만으로 해결하지 않는다.

### D. 점수/등급 조건이 화면과 다름
- 원인: 화면이 오래됨.
- 해결: 도전 클릭 시 서버 최신값으로 재검증한다.

### E. 재도전 cooldown/횟수 제한
- 정책: 현재 미확정이면 `TBD`. 구현자가 임의 제한을 만들지 않는다.

## UI
- 가능: `승급전 시작`
- 진행 중: `진행 중인 승급전 이어하기`
- 불가: 정확한 불가 사유 표시
