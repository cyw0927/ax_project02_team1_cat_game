# 07. 승급 성공 처리 및 보상

## 목적
SUCCESS로 확정된 challenge에 대해 승급 결과와 보상을 중복 없이 반영한다.

## 정상 흐름
1. challenge.status가 SUCCESS인지 확인한다.
2. 사용자 랭킹/등급 반영 대상인지 확인한다.
3. 아직 반영되지 않은 승급 결과를 적용한다.
4. 성공 보상 자격과 기존 지급 여부를 확인한다.
5. 미지급이면 재화 증가와 지급 상태 기록을 하나의 짧은 트랜잭션으로 처리한다.
6. 최신 랭킹/재화 상태를 반환한다.

## 발생 가능한 변수
### A. 결과 화면 새로고침
- 위험: 승급/보상 로직 재실행.
- 해결: 결과 조회와 상태 변경을 분리하고 이미 반영된 승급/보상은 다시 적용하지 않는다.

### B. commit 성공 후 응답 유실
- 해결: 재요청 시 기존 반영 상태를 확인하고 최신 결과만 반환한다.

### C. 두 기기에서 동시에 결과 확인
- 위험: 이중 승급 반영/이중 보상.
- 해결: 승급 이벤트와 보상 이벤트를 서버/DB에서 멱등하게 식별한다.

### D. 랭킹 반영 성공, 보상 실패
- 현재 스키마와 최종 정책에 따라 같은 트랜잭션으로 묶을지 별도 멱등 이벤트로 처리할지 설계 필요.
- 어느 경우든 재시도 시 승급을 두 번 적용하면 안 된다.

## DB/API 영향
- RANK_CHALLENGES SUCCESS 확인
- RANKING_PARTICIPANTS 최신 점수/상태
- USERS.balance 등 최종 확정 재화 필드
- 보상 멱등 기록 위치는 스키마 결정 필요

## 트랜잭션/동시성
- 장시간 lock 금지.
- 단순 재화 증가는 DB 원자 증가 우선.
- 1회성 보상은 UNIQUE/멱등 키 등으로 중복 보호.
