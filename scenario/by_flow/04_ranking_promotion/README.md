# 랭킹 / 승급전 흐름 시나리오

## 전체 흐름

`랭킹 진입 → 랭킹 확인 → 승급전 도전 → 문제 풀이 → 성공/실패 판정 → 성공 시 승급 보상 및 재화 획득 / 실패 시 종료`

랭킹과 승급전은 사용자의 현재 점수/그룹과 도전 상태를 함께 다룬다. 특히 승급전은 **도전 중복 생성, 제한 시간, 문제 저장, 성공/실패 판정, 보상 중복**이 핵심 변수다.

---

## 1. 랭킹 진입 및 현재 순위 확인

### 정상 흐름
1. 홈에서 `랭킹/승급전` 선택.
2. 사용자가 속한 ranking group 확인.
3. group 참가자와 current_rank_score 조회.
4. 사용자 자신의 순위/점수/도전 가능 상태 표시.

### 변수
- 사용자가 ranking group에 아직 없음: 신규 사용자, 그룹 배정 누락.
- 그룹은 있지만 참가 row 없음.
- 동점자가 여러 명: 동점 처리 기준 TBD.
- 점수가 다른 화면에서 갱신됨: 서버 최신값 사용.
- 랭킹 목록이 많음: pagination 필요 가능.

### UI
`순위 없음`과 `조회 실패`를 구분. 도전 불가 사유가 있으면 버튼 옆에 명확히 표시.

---

## 2. 승급전 도전 가능 여부 확인

### 목적
현재 사용자가 새로운 승급전을 시작할 수 있는지 판단한다.

### 확인 후보
- 현재 진행 중인 challenge 존재 여부
- 랭킹 점수 또는 등급 조건
- 재도전 cooldown 존재 여부
- 그룹 상태

정확한 도전 조건은 아직 확정된 정책만 사용하며 나머지는 `TBD`.

### 변수
- 이미 IN_PROGRESS인 도전 존재: 새 challenge 중복 생성 금지, 기존 도전 이어가기 제공.
- 이전 challenge가 TIMEOUT인데 상태 갱신이 안 됨: 현재 시간과 expires_at 비교 후 정리 필요.
- 두 탭에서 동시에 도전 시작 클릭: 둘 다 새로운 challenge를 만들 수 있는 race.

### 해결
`한 사용자/그룹에 활성 challenge 1개` 규칙이 필요하다면 DB 제약 또는 짧은 동시성 제어로 보장한다. 단순 프론트 버튼 잠금으로 해결하지 않는다.

## 3. 승급전 생성

### 정상 흐름
1. 서버가 도전 가능 상태 재검증.
2. RANK_CHALLENGES 생성.
3. 문제 목록을 확정하고 RANK_CHALLENGE_TASKS에 순서대로 저장.
4. started_at, expires_at 기록.
5. challenge_id 반환.

### 변수
- 문제 목록 생성 중 일부 task 비활성.
- 동일 task 중복 선택.
- task_order 중복.
- expires_at 클라이언트 조작.

### 해결
- 제한 시간 기준은 서버가 권위.
- challenge-task unique 제약 활용.
- 문제 선정 규칙은 서버가 처리.
- 현재 API가 client task_ids/expires_at를 받는다면 최종 설계 전에 서버 권위 방식으로 바꿀지 검토 필요.

## 4. 문제 풀이 및 중간 저장

### 정상 흐름
- 현재 challenge의 문제 순서대로 표시.
- 사용자가 코드 작성.
- saved_code에 중간 저장 가능.
- 제출/채점 후 is_passed 갱신.

### 변수
- 브라우저 새로고침: saved_code로 복구.
- 저장 중 네트워크 끊김: 마지막 성공 저장까지만 복구.
- 제한 시간 종료 직전 제출.
- 이미 통과한 문제 재제출.
- challenge status가 더 이상 IN_PROGRESS가 아닌데 저장 요청.

### 해결
모든 저장/제출 시 서버가 challenge 상태와 서버 현재 시간을 재확인한다. 클라이언트 타이머는 표시용.

---

## 5. 제한 시간

### 변수 A. 브라우저 시간을 변경
- 해결: expires_at과 서버 현재 시간으로 판정.

### 변수 B. 서버 처리 중 제한 시간 경과
- 제출 수락 시각 기준인지 채점 완료 시각 기준인지 정책이 필요.
- 사용자에게 공정성을 주려면 요청 수락 시간을 기록해 판정하는 방식 검토 가능하나 최종 결정은 TBD.

### 변수 C. 사용자가 페이지를 닫았다가 복귀
- challenge가 살아 있으면 남은 시간 계산.
- 이미 만료면 TIMEOUT으로 전환 후 결과 표시.

---

## 6. 성공 / 실패 판정

### 성공 조건 후보
- 모든 challenge task 통과
- 일정 개수 이상 통과
- 점수/시간 기준

현재 합격 기준은 `TBD`.

### 변수
- 마지막 문제 두 개가 동시에 채점 완료.
- 성공 판정과 timeout 판정이 거의 동시에 실행.
- 같은 challenge 결과 판정 함수가 재실행.

### 해결
IN_PROGRESS 상태에서 SUCCESS/FAILED/TIMEOUT 중 하나로만 전이하도록 조건부 update 또는 짧은 row lock 적용 검토. 이미 종료 상태면 결과를 다시 바꾸지 않는다.

---

## 7. 성공 시 승급 처리

### 정상 흐름
1. SUCCESS 확정.
2. 사용자 ranking score/등급 반영.
3. 성공 보상 자격 확인.
4. 미지급이면 재화 지급.
5. 최종 랭킹 정보 반환.

### 변수
- 승급 상태 업데이트는 됐는데 보상 지급 실패.
- 보상은 됐는데 결과 응답 유실.
- 동일 성공 결과 처리 두 번.

### 해결
승급 결과와 보상 지급을 멱등하게 설계. 보상 식별 키가 필요하며 현재 스키마에 없다면 추가 설계 검토.

### 보상
승급 성공 보상 액수/종류는 `TBD`.

## 8. 실패 / TIMEOUT

### 정상 흐름
- challenge 종료 상태 기록.
- 실패 사유/통과 문제 수 표시.
- 재도전 가능 여부 안내.

### 변수
- 실패 시 이미 풀어둔 saved_code 유지 여부.
- 재도전 시 같은 문제 재사용 여부.
- cooldown 여부.

모두 비즈니스 정책 미확정이면 TBD.

## 9. 랭킹 재조회

승급 성공 후 화면은 로컬에서 순위 숫자만 임의 증가시키지 않고 서버에서 최신 ranking participant 목록을 다시 받아 표시한다.
