# 사용자 흐름 중심 시나리오

이 폴더는 기능 목록이 아니라 **사용자가 게임을 실제로 진행하는 순서**를 기준으로 시나리오를 읽기 위한 문서 묶음이다.

전체 흐름은 다음 순서로 이해하면 된다.

```text
로그인
  ↓
홈
  ├─ 일일 미션 ──→ 복습 문제 확인 → 풀이/제출 → 채점 → 보상 ─┐
  ├─ 학습 ───────→ 문제 선택 → 코드 작성 → 제출 → 채점 → 보상 ─┤
  ├─ 배틀 ───────→ 방 참가 → Ready → 시작 → 풀이 → 경쟁 → 보상 ─┤
  ├─ 랭킹/승급전 → 랭킹 확인 → 승급전 → 풀이 → 성공/실패 → 보상 ─┤
  ├─ 상점 ◀────────────────────────────────────────────── 재화 획득
  ├─ 가챠 ◀────────────────────────────────────────────── 재화 획득
  └─ 하우징 ◀── 가구 구매 / 고양이 획득
```

## 읽는 순서

1. [01_daily_mission](./01_daily_mission/README.md) — 홈에서 일일 미션에 진입한 뒤 복습 문제를 확인하고 보상까지 받는 흐름
2. [02_learning](./02_learning/README.md) — 일반 학습 문제를 선택하고 제출·채점·정답 보상까지 가는 흐름
3. [03_battle](./03_battle/README.md) — 방 참가, Ready, 게임 시작, 문제 풀이, 점수 경쟁, 결과 보상 흐름
4. [04_ranking_promotion](./04_ranking_promotion/README.md) — 랭킹 확인, 승급전 도전, 성공/실패 및 보상 흐름
5. [05_shop](./05_shop/README.md) — 재화 확인, 가구 구매, 인벤토리 반영, 하우징 적용 흐름
6. [06_gacha](./06_gacha/README.md) — 재화 사용, 뽑기 결과, 신규/중복 고양이 처리, 하우징 배치 흐름
7. [07_housing](./07_housing/README.md) — 가구와 고양이를 불러오고 배치·수정·상호작용·저장하는 흐름
8. [08_currency](./08_currency/README.md) — 각 기능에서 재화가 어디서 생기고 어디서 사용되며 중복/동시성 문제를 어떻게 막는지 보는 흐름

## 각 문서에서 반드시 확인할 항목

각 단계는 단순히 `정상일 때 무엇을 한다`만 적지 않는다. 다음 항목을 단계별로 확인한다.

- 단계 목적
- 정상 흐름
- 발생 가능한 변수와 예외
- 변수가 발생하는 이유
- 시스템이 감지하는 방법
- 서버/DB 처리 방법
- 사용자에게 보여줄 UI와 메시지
- 중복 요청, 재시도, 동시성, 네트워크 단절
- 다음 단계로 넘어가는 조건
- 다음 단계에 미치는 영향
- 테스트해야 할 케이스

## 문서 관계

`by_flow`를 먼저 읽다가 API, DB, 동시성, Docker 채점, 상태값 같은 구현 근거가 더 필요하면 [`../by_function`](../by_function/) 문서를 참고한다.

`by_flow`는 **이용 흐름을 이해하기 위한 문서**, `by_function`은 **기능별 구현 근거를 찾기 위한 문서**다.

## 비즈니스 규칙 주의

아직 확정되지 않은 값은 문서 편의를 위해 임의로 정하지 않는다. 특히 아래 항목은 기존 합의나 근거가 없는 경우 `TBD` 상태를 유지한다.

- 가챠 1회 비용
- 가챠 확률 및 천장
- 일일 미션/학습/배틀/승급 보상 수치
- 승급 성공 기준
- 재화 종류를 추가로 분리할지 여부

문서를 읽을 때 `TBD`는 누락이 아니라 **추가 합의가 필요한 의사결정 지점**으로 본다.
