# 배틀 6단계 — 점수 경쟁

## 목적
각 참가자의 문제 풀이 결과를 일관된 기준으로 점수에 반영하고, 동시에 여러 채점 결과가 들어와도 점수가 누락되거나 중복 반영되지 않도록 한다.

## 정상 흐름
1. `05_solve_submit.md`에서 제출이 접수된다.
2. 채점 결과가 서버에서 확정된다.
3. 서버는 해당 결과가 점수 반영 대상인지 확인한다.
4. 아직 반영되지 않은 유효 결과라면 정해진 점수 규칙에 따라 참가자 점수를 갱신한다.
5. 최신 개인/팀 점수를 참가자에게 전달한다.
6. 다음 문제 풀이 또는 종료 조건 확인으로 이동한다.

## 발생 가능한 변수

### 변수 A. 같은 attempt가 두 번 점수 반영됨
- **원인**: 채점 완료 이벤트 재실행, API 재시도, reconnect 후 동일 결과 재처리.
- **위험**: 한 번의 정답이 두 번 이상 점수에 반영된다.
- **감지**: attempt_id와 점수 반영 여부를 연결해 확인한다.
- **해결**: 점수 반영은 멱등하게 처리해야 한다. 프론트가 중복 이벤트를 숨기는 것만으로는 부족하다.

### 변수 B. 채점 완료 순서가 제출 순서와 다름
- **원인**: 문제별 실행 시간 차이, Docker queue 대기 시간 차이.
- **위험**: 먼저 제출한 사람이 나중에 반영되어 순위 화면이 순간적으로 뒤집힐 수 있다.
- **해결**: 점수 규칙이 `제출 시각`, `채점 완료 시각`, `정답 확정 시각` 중 무엇을 기준으로 하는지 팀에서 확정해야 한다. 현재는 `TBD`.
- **UI**: 점수가 확정되지 않은 제출은 `채점 중`으로 표시하고 확정 점수처럼 보여주지 않는다.

### 변수 C. 두 문제가 거의 동시에 정답 처리
- **원인**: 여러 탭, 빠른 연속 제출, 병렬 채점.
- **위험**: Python에서 기존 current_score를 읽고 더한 뒤 저장하면 lost update 가능.
- **해결**: 가능한 경우 DB 원자 증가 연산을 사용한다.

### 변수 D. 팀전에서 개인 점수와 팀 점수가 다름
- **원인**: 개인 점수 합계와 팀 집계 시점 차이.
- **해결**: 팀 점수를 별도 저장할지 참가자 점수 합계로 계산할지 `TBD`. 한 요청에서는 한 가지 권위 상태만 사용한다.

### 변수 E. 오답/시스템 오류/timeout 처리 차이
- **원인**: 채점 실패 원인이 다름.
- **위험**: 시스템 오류를 오답으로 처리하면 사용자에게 불리한 점수가 기록될 수 있다.
- **해결**: 정답, 오답, 사용자 코드 timeout, 인프라 장애를 구분한다. 어떤 경우 감점되는지는 점수 규칙 `TBD`.

### 변수 F. 방이 FINISHED인데 늦은 채점 결과가 도착
- **원인**: 종료 요청과 Docker 채점 완료가 겹침.
- **위험**: 종료 결과 확정 뒤 점수가 바뀐다.
- **해결**: 종료 시점에 어떤 제출까지 유효한지 기준을 정해야 한다. `제출 접수 시각`을 기준으로 할지, 종료 전에 채점 완료된 것만 인정할지는 `TBD`.

### 변수 G. 클라이언트 점수와 서버 점수가 다름
- **원인**: WebSocket/폴링 누락, 오래된 응답, 재접속.
- **해결**: 서버 DB가 권위 상태다. 재접속 시 최신 ROOM_PARTICIPANTS 점수를 다시 조회한다.

## DB/API 영향
- `ROOM_PARTICIPANTS.current_score` 갱신.
- 점수 반영의 원인이 되는 attempt/task 식별이 필요하다.
- 현재 ERD에 battle score event ledger가 없다면 중복 반영 방지용 스키마 추가 여부를 구현 전에 결정한다.

## 동시성 원칙
- 단순 점수 증가라면 가능한 한 원자적 `UPDATE ... SET current_score = current_score + :delta`를 우선 검토한다.
- 오래 걸리는 Docker 채점 동안 ROOM/ROOM_PARTICIPANTS row lock을 유지하지 않는다.
- 여러 조건을 동시에 검사해야 하는 상태 전이만 짧은 트랜잭션으로 처리한다.

## UI
- 확정 점수와 채점 중 상태를 구분.
- 개인전은 개인 순위, 팀전은 팀 점수/개인 기여 표시 가능.
- 네트워크 재연결 후 서버 점수로 즉시 동기화.
- 점수 계산 규칙이 확정되기 전 임의 공식 표시 금지.
