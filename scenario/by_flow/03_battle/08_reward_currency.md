# 배틀 8단계 — 결과 보상 및 재화 연결

## 목적
배틀 최종 결과에 따라 보상 자격을 판정하고, 같은 경기 결과가 여러 번 조회되거나 재요청돼도 보상이 중복 지급되지 않도록 한 뒤 최신 재화 상태를 다음 흐름으로 전달한다.

## 정상 흐름
1. `07_finish_result.md`에서 방 결과가 최종 확정된다.
2. 서버가 각 참가자의 보상 자격을 판정한다.
3. 해당 room/user 기준으로 이미 배틀 보상이 지급됐는지 확인한다.
4. 미지급이고 자격이 있다면 보상 지급과 지급 기록을 하나의 짧은 트랜잭션으로 처리한다.
5. 최신 재화 잔액과 보상 상태를 반환한다.
6. 사용자는 홈, 상점, 가챠, 하우징 등 다음 흐름으로 이동한다.

## 발생 가능한 변수

### 변수 A. 결과 화면 새로고침 때 보상 로직 재실행
- **원인**: 결과 페이지 진입을 보상 트리거로 구현.
- **위험**: 페이지 새로고침 횟수만큼 중복 지급.
- **해결**: `결과 조회`와 `보상 지급`을 분리하고, 서버에서 room/user/reward_type 기준 멱등성을 보장한다.

### 변수 B. 결과 응답 유실 후 재요청
- **원인**: 보상 transaction commit 후 네트워크 단절.
- **위험**: 사용자는 실패로 생각하고 다시 요청.
- **해결**: 이미 지급됐으면 다시 지급하지 않고 기존 지급 상태와 최신 balance를 반환한다.

### 변수 C. 같은 사용자가 여러 기기에서 동시에 결과 확인
- **원인**: PC/모바일 또는 여러 탭.
- **위험**: 두 요청이 동시에 미지급 상태를 읽음.
- **해결**: 단순 `SELECT 미지급 → INSERT/UPDATE`만 믿지 않는다. UNIQUE, 멱등 키, 원자적 상태 전이 중 실제 스키마에 맞는 방법으로 한 번만 성공시킨다.

### 변수 D. 보상 판정 중 결과가 아직 완전히 확정되지 않음
- **원인**: 늦은 채점/집계 정책이 남아 있음.
- **해결**: `결과 확정` 상태 전에는 보상을 지급하지 않는다. 화면에서 `집계 중`과 `보상 완료`를 구분한다.

### 변수 E. 승자/패자/순위별 보상 차등
- **원인**: 최종 경제 정책.
- **정책**: 어떤 순위에 얼마를 줄지는 현재 확정 전이면 `TBD`. 문서에서 임의 숫자를 만들지 않는다.

### 변수 F. 중도 이탈 참가자의 보상
- **원인**: 참가 기록은 있으나 게임 도중 연결 종료.
- **쟁점**: 참가 보상/순위 보상 자격을 유지할지.
- **정책**: `TBD`. 클라이언트 연결 상태만으로 자동 박탈하지 않는다.

### 변수 G. 보상 지급 중 DB 오류
- **위험**: balance만 증가하고 지급 기록이 없거나 그 반대.
- **해결**: 재화 증가와 지급 상태 기록을 하나의 짧은 트랜잭션으로 처리한다. 실패 시 전체 rollback.

### 변수 H. 다른 보상과 동시에 balance 증가
- **예**: 배틀 보상과 학습 보상 동시 확정.
- **위험**: read-modify-write 방식이면 lost update.
- **해결**: 가능한 한 DB 원자 증가 연산을 사용한다.

### 변수 I. 화면 잔액이 오래됨
- **원인**: 다른 탭에서 상점 구매/가챠 사용.
- **해결**: 서버 balance가 권위 상태. 배틀 보상 완료 응답의 최신 잔액으로 갱신하고 다음 거래에서도 다시 서버 검증한다.

## 보상 멱등성 식별 후보
최종 구현 시 최소한 아래 정보를 조합해 같은 배틀 보상을 식별할 수 있어야 한다.

- room_id
- user_id
- reward_type

현재 19-table ERD에 범용 reward ledger가 확정되어 있는 것은 아니므로 실제 테이블/컬럼 추가 여부는 구현 전 별도 결정한다.

## DB/API 영향
- `USERS.balance` 등 실제 재화 필드 증가.
- `ROOMS.status = FINISHED` 확인.
- `ROOM_PARTICIPANTS`에서 참가/최종 점수 확인.
- 지급 여부를 권위 있게 저장할 위치가 필요하다.

## 트랜잭션/락 원칙
- Docker 채점과 보상 transaction은 분리한다.
- 보상 transaction은 짧게 유지한다.
- 단순 잔액 증가는 원자 UPDATE 우선.
- 중복 지급은 UNIQUE/멱등 조건으로 우선 보호하고 불필요한 장시간 row lock을 만들지 않는다.

## UI
- 신규 지급: `배틀 보상을 획득했습니다.`와 획득 내역 표시.
- 이미 지급됨: 새 보상 애니메이션을 반복하지 않는다.
- 결과 확정 전: `결과 집계 중`.
- 지급 실패: 화면에서 임의로 잔액을 더하지 않고 재조회/재시도.

## 다음 흐름

### 홈
`배틀 종료 → 결과/보상 확인 → 홈`

### 상점
`배틀 보상 → 최신 balance → 상점 → 서버 가격/잔액 검증 → 구매`

### 가챠
`배틀 보상 → 최신 재화 → 가챠 → 서버 비용/정책 검증`

### 하우징
배틀 보상 자체가 하우징을 직접 바꾸는 것은 아니다. 상점/가챠를 통해 획득한 가구/고양이가 이후 하우징에 반영된다.
