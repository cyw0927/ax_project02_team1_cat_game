# 배틀 7단계 — 종료 및 결과 확정

## 목적
게임 종료 조건을 만족했을 때 방을 한 번만 종료 상태로 전환하고, 이후 늦게 도착하는 요청이나 채점 결과 때문에 최종 순위가 흔들리지 않도록 결과 기준점을 확정한다.

## 정상 흐름
1. 서버가 종료 조건을 확인한다.
2. `ROOMS.status`가 `IN_PROGRESS`인지 재검증한다.
3. 종료 시점에 인정할 점수/제출 범위를 확정한다.
4. 방 상태를 `FINISHED`로 전환한다.
5. 참가자별 최종 점수와 개인전/팀전 순위를 계산한다.
6. 결과 데이터를 조회 가능한 상태로 저장하거나 재현 가능한 권위 상태를 남긴다.
7. 클라이언트는 결과 화면으로 이동한다.

## 발생 가능한 변수

### 변수 A. 종료 요청이 여러 번 들어옴
- **원인**: 호스트 더블클릭, 타이머 종료 이벤트와 수동 종료가 동시에 실행, 재시도.
- **위험**: 결과 계산/보상 로직이 여러 번 실행될 수 있다.
- **해결**: `IN_PROGRESS → FINISHED` 상태 전이는 한 번만 성공해야 한다. 이미 FINISHED면 새 종료 처리를 만들지 않고 기존 결과를 반환한다.

### 변수 B. 마지막 제출과 종료가 동시에 발생
- **원인**: 제한시간 직전 제출.
- **쟁점**: 제출 요청을 서버가 종료 전 수락했지만 채점 완료는 종료 후일 수 있다.
- **해결**: 어떤 제출을 유효로 인정할지 기준이 필요하다. `제출 접수 시각`, `채점 완료 시각`, `종료 시각` 중 기준은 `TBD`.
- **금지**: 클라이언트 타이머만 보고 임의 판정.

### 변수 C. 종료 뒤 늦은 채점 결과 도착
- **위험**: 이미 보여준 최종 순위가 뒤집힐 수 있다.
- **해결**: 종료 시 인정 범위를 고정한다. 유효 pending attempt를 종료 후 마저 기다려 결과를 확정할지, 즉시 종료할지는 정책 `TBD`.

### 변수 D. 참가자 한 명이 결과 직전 연결 종료
- **원인**: 브라우저 종료, 네트워크 끊김.
- **해결**: 연결 여부와 결과 참가 자격을 동일하게 보지 않는다. 이미 참가 기록이 있는 사용자는 서버 결과에서 누락되지 않아야 한다.

### 변수 E. 동점
- **원인**: 동일 점수.
- **해결**: 동점자 순위를 공동 순위로 할지, 제출 속도/정답 수 등 보조 기준을 적용할지는 `TBD`.
- **UI**: 정책 확정 전 임의로 먼저 제출한 사람을 승자로 만들지 않는다.

### 변수 F. 팀전에서 팀원이 중간 이탈
- **원인**: 네트워크/사용자 종료.
- **쟁점**: 이탈자의 이미 획득한 점수를 팀 점수에 유지할지 여부.
- **정책**: `TBD`. 서버가 단순히 현재 연결된 참가자만 합산하면 안 된다.

### 변수 G. 결과 조회 중 DB/API 장애
- **해결**: FINISHED 상태가 이미 commit됐다면 결과 화면 실패가 게임 자체를 다시 IN_PROGRESS로 되돌리면 안 된다.
- **UI**: `결과를 불러오지 못했습니다. 다시 시도해주세요.` + 재조회.

### 변수 H. 서버 재시작
- **위험**: 결과가 메모리에만 있다면 유실.
- **해결**: 최종 상태는 DB에서 복원 가능해야 한다. 결과 저장 방식/별도 테이블 여부는 구현 전에 결정한다.

## 결과 계산 원칙
- 클라이언트가 보낸 최종 점수를 그대로 믿지 않는다.
- 서버의 `ROOM_PARTICIPANTS.current_score` 및 확정된 참가 상태를 기준으로 한다.
- 팀전이라면 team_name별 집계 규칙을 일관되게 적용한다.
- 동점 규칙이 미정이면 `TBD`로 둔다.

## DB/API 영향
- `ROOMS.status = FINISHED` 상태 전이.
- `ROOM_PARTICIPANTS.current_score`를 최종 결과 계산에 사용.
- 최종 순위/종료 시각/결과 snapshot을 별도 저장할지 여부는 스키마 결정 필요.

## 트랜잭션/락
- 종료 상태 전이와 결과 확정에 필요한 DB 변경은 짧은 트랜잭션으로 처리한다.
- 오래 기다리는 채점/Docker 작업을 종료 transaction 안에서 기다리지 않는다.
- 종료와 참가/시작/점수 반영의 동시 요청은 room.status를 서버에서 재검증한다.

## UI
- 최종 개인/팀 순위.
- 점수.
- 승리/패배 또는 순위 표시.
- 결과 확정 중인 상태가 있다면 `결과 집계 중`을 별도로 보여준다.
- 결과 조회 실패와 게임 실패를 구분한다.
