# 06. 좌표·충돌·화면 표현

## 목적
하우징의 가구 위치와 고양이 이동 좌표가 화면 크기나 배경 변경 때문에 깨지지 않도록 좌표계와 충돌 책임을 분리한다.

## 정상 흐름
1. 서버는 합의된 position_data 규격을 저장한다.
2. 프론트는 서버 좌표를 현재 화면 크기에 맞게 변환한다.
3. 가구는 저장 좌표를 기준으로 렌더링한다.
4. 고양이의 순간 이동 좌표는 클라이언트 이동 시스템이 관리한다.
5. 최소한의 이동 가능 영역과 가구 obstacle 영역을 적용한다.

## 발생 가능한 변수
### A. 브라우저 크기 변경
- 원인: 반응형 UI, 모바일/PC 차이.
- 위험: 단순 픽셀 좌표를 저장하면 다른 해상도에서 위치가 달라진다.
- 해결: percentage/논리 격자/월드 좌표 중 팀 공통 규격을 확정한다. 현재 최종 규격은 TBD.

### B. 배경 이미지가 변경돼 obstacle이 실제 가구와 안 맞음
- 원인: 하우스 이미지 교체, CSS 배치 변경.
- 해결: obstacle 정의를 배경 이미지에 강하게 하드코딩하지 않고 실제 배치 object 기반으로 확장하는 방안을 우선한다.

### C. 개인 prototype 좌표계와 공용 프론트 좌표계가 다름
- 해결: 서버 position_data를 특정 화면 구현의 픽셀 값으로 고정하지 않는다. 변환 계층을 둔다.

### D. 가구 겹침
- 정책: 겹침을 어느 수준까지 금지할지 TBD.
- 최소 검증: 허용 범위 밖 좌표, 잘못된 타입, 지나치게 큰 payload는 서버에서 거절한다.

### E. 고양이가 가구를 통과함
- MVP에서는 프론트 obstacle 회피로 처리 가능.
- 서버가 매 프레임 충돌을 검증하지 않는다.

## DB/API 영향
- PLACED_OBJECTS.position_data jsonb
- 향후 최종 schema 확정 시 migration 필요 가능

## UI
- 드래그 preview와 저장된 확정 위치를 구분.
- 저장 불가 위치라면 사용자가 이해할 수 있게 원래 위치로 복귀/보정한다.
