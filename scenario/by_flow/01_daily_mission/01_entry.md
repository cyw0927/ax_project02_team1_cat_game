# 01. 일일 미션 진입

## 목적
사용자가 로그인 후 홈에서 `일일 미션`을 선택했을 때, 오늘 수행할 복습 미션이 존재하는지와 현재 진행 상태를 안전하게 확인하는 단계다. 이 단계의 핵심은 **클라이언트 화면을 여는 것**이 아니라, 서버가 오늘 기준 미션 상태를 권위 있게 결정해 다음 단계로 보낼 수 있는 상태를 만드는 것이다.

## 정상 흐름
1. 사용자가 로그인한다.
2. 홈에서 `일일 미션`을 선택한다.
3. 서버는 인증된 사용자와 서버 기준 날짜를 확인한다.
4. 오늘의 복습 대상 존재 여부, 전체 문제 수, 완료 문제 수, 보상 상태를 계산한다.
5. 클라이언트는 `시작`, `이어하기`, `오늘 완료`, `오늘 문제 없음` 중 현재 상태에 맞는 UI를 보여준다.
6. 풀 수 있는 문제가 있으면 `02_review_tasks.md` 단계로 이동한다.

## 발생 가능한 변수

### A. 서버 날짜와 사용자 기기 날짜가 다름
- **왜 생기는가**: PC/휴대폰 시간이 틀림, 해외 체류, VPN, 자정 전후 접속.
- **위험**: 클라이언트 날짜를 기준으로 하면 같은 날 미션이 두 번 생기거나 오늘 미션이 사라질 수 있다.
- **감지**: 서버가 자체 시간과 서비스 기준 타임존으로 날짜를 계산한다. 클라이언트가 보내는 날짜는 권위값으로 사용하지 않는다.
- **해결**: 서비스 표준 타임존은 팀 결정 전까지 `TBD`. 결정되기 전 코드에 임의로 Asia/Seoul을 고정하지 않는다.
- **UI**: 사용자는 단순히 `오늘의 미션`을 보되, 날짜 경계 문제를 조사할 수 있도록 서버 로그에는 기준 날짜를 남긴다.

### B. 오늘 복습할 문제가 0개
- **가능 원인**: 신규 사용자, 과거 학습 데이터 부족, 모든 복습 후보 완료, 후보 TASK 비활성화, 복습 생성 규칙 미실행.
- **감지**: 조회 성공인데 유효한 복습 대상이 0개인 상태와 조회 실패를 구분한다.
- **해결**: 오류로 취급하지 않고 `오늘 복습할 문제가 없습니다` 상태로 응답한다.
- **미정 규칙**: 0문제일 때 올클리어 보상을 자동 지급할지는 `TBD`.
- **다음 단계**: 문제 풀이로 보내지 않고 완료/안내 화면으로 분기한다.

### C. 일일 미션 상태 조회 실패
- **가능 원인**: DB 연결 오류, API 예외, 인증 만료, 네트워크 단절.
- **감지**: HTTP 오류/타임아웃과 정상 0건 응답을 구분한다.
- **해결**: 빈 미션으로 위장하지 않는다. 재시도 가능한 실패 상태를 반환한다.
- **UI**: `미션 정보를 불러오지 못했습니다. 다시 시도해주세요.` + 재시도 버튼.

### D. 여러 탭/여러 기기에서 동시에 진입
- **왜 생기는가**: PC와 모바일 동시 사용, 브라우저 탭 중복.
- **위험**: 각 화면의 진행률이 다르게 보일 수 있다.
- **해결**: 읽기는 허용하되 진행률과 보상 상태는 서버 DB를 기준으로 한다. 화면 재진입/새로고침 시 최신 상태를 다시 조회한다.

### E. 로그인은 됐지만 사용자 레코드가 없음
- **가능 원인**: 회원 생성 트랜잭션 실패, 삭제된 계정, 인증 시스템과 USERS 동기화 실패.
- **감지**: 인증 토큰의 user_id로 USERS 조회 실패.
- **해결**: 일일미션을 임의 생성하지 않고 사용자 초기화/계정 복구 흐름으로 보낸다.

## DB/API 영향
- 핵심 식별값은 `user_id + 서버 기준 날짜`다.
- 현재 ERD에 일일미션 전용 테이블이 확정되어 있지 않으므로 이 문서에서 임의 테이블을 추가하지 않는다.
- 로그인 시 지급되는 출석 100원과 일일미션 보상은 다른 흐름이다. 두 보상을 같은 처리로 합치지 않는다.

## 동시성/멱등성
- 단순 조회에는 row lock이 필요하지 않다.
- 진입 요청을 여러 번 보내도 새로운 보상이나 새로운 attempt가 생기면 안 된다.
- 미션 생성이 쓰기 작업을 포함하게 될 경우, 동일 사용자·동일 날짜에 중복 생성되지 않는 DB 제약 또는 멱등 처리 정책이 필요하다.

## UI 상태 제안
- `LOADING`: 오늘 상태 조회 중
- `READY`: 미완료 문제 존재
- `IN_PROGRESS`: 일부 완료
- `COMPLETED`: 모두 완료
- `EMPTY`: 정상 조회됐지만 문제 0개
- `ERROR`: 조회 실패

상태명은 구현 전 최종 API 계약에 맞춰 조정할 수 있으며, 여기서 enum을 확정하는 것은 아니다.

## 다음 단계 조건
- 유효한 미완료 복습 문제가 1개 이상 존재 → `02_review_tasks.md`
- 모두 완료 → 보상 상태 확인
- 0개 → 미션 없음/완료 정책에 따른 종료
- 조회 실패 → 재시도
