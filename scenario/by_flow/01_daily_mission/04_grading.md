# 04. 채점

## 목적
제출된 코드를 격리된 실행 환경에서 채점하고, 정답/오답/시스템 실패를 구분해 attempt의 최종 결과를 확정하는 단계다.

## 정상 흐름
1. PENDING attempt가 백그라운드 작업 대상이 된다.
2. 애플리케이션 실행 슬롯(semaphore/queue)을 기다린다.
3. 슬롯 확보 후 미리 준비된 Docker grading image로 컨테이너를 실행한다.
4. CPU, 메모리, 네트워크, 파일시스템 제한을 적용한다.
5. 테스트 결과를 수집한다.
6. 컨테이너를 제거한다.
7. 별도의 짧은 DB 트랜잭션으로 attempt 최종 결과를 갱신한다.
8. 클라이언트는 polling 등으로 결과를 확인한다.

## 발생 가능한 변수

### A. 채점 대기열이 길어짐
- **원인**: 동시 제출 증가, 실행 슬롯 수보다 많은 요청.
- **위험**: 무제한 컨테이너 생성 시 호스트 메모리 고갈.
- **해결**: 컨테이너 생성 전에 애플리케이션 레벨 실행 개수를 제한한다. 현재 MVP 기본 방향은 소수의 동시 실행 슬롯이다.
- **UI**: 가능하면 `채점 대기 중`과 `채점 중`을 구분한다.

### B. 사용자 코드 무한루프
- **감지**: 실행 timeout.
- **해결**: 해당 컨테이너만 종료하고 제거한다. DB나 다른 사용자의 실행까지 영향을 주지 않는다.
- **결과**: 오답과 시스템 오류 중 어떤 최종 status로 둘지는 확정된 status 정책을 따른다. 미확정이면 `TBD`.

### C. 메모리 초과
- **감지**: 컨테이너 resource limit 초과/OOM 종료 코드.
- **해결**: 해당 작업만 실패 처리하고 컨테이너 제거.
- **금지**: 호스트 전체가 메모리 부족 상태가 될 때까지 컨테이너를 무제한 생성하는 방식.

### D. Docker daemon이 꺼져 있음
- **원인**: Docker Desktop 종료, daemon 오류.
- **감지**: Docker SDK 연결/실행 예외.
- **해결**: attempt를 영구 PENDING으로 방치하지 않는 실패 복구 정책 필요. 자동 재시도 횟수는 `TBD`.
- **UI**: `채점 시스템 오류입니다. 잠시 후 다시 시도해주세요.`와 오답 메시지를 구분한다.

### E. 서버 프로세스 재시작
- **현재 위험**: FastAPI BackgroundTasks 기반 MVP는 작업 내구성이 없다.
- **영향**: DB에는 PENDING인데 실제 백그라운드 작업이 사라질 수 있다.
- **해결**: PENDING stuck 복구 정책 또는 향후 durable queue 검토. 현재 한계를 숨기지 않는다.

### F. 테스트케이스 데이터 오류
- **원인**: 잘못된 expected result, 깨진 test_cases 포맷.
- **위험**: 정답 코드가 오답 처리될 수 있다.
- **해결**: 사용자 코드 오류와 채점 데이터 오류를 구분할 수 있는 로그/운영 절차 필요. test_cases 최종 포맷은 아직 확정 전이면 `TBD`.

### G. 결과 저장 시 DB 오류
- **상황**: Docker 실행은 끝났지만 최종 UPDATE가 실패.
- **해결**: 컨테이너를 다시 무작정 실행하기 전에 attempt 현재 상태를 확인해야 한다. 결과 재저장 가능 여부와 재실행 정책을 분리한다.

### H. 클라이언트 polling 중 네트워크 끊김
- **해결**: 채점 작업은 계속될 수 있다. 재접속 후 attempt_id로 상태를 다시 조회한다.

## 자원 격리 원칙
- memory: 제한 적용
- CPU: 제한 적용
- network: none
- filesystem: read-only
- timeout: 적용
- 출력 크기: 상한 필요

세부 수치는 현재 sandbox 설정/팀 결정에 맞추며 문서에서 새 수치를 임의 확정하지 않는다.

## DB 트랜잭션 원칙
- Docker 실행 중 transaction 유지 금지.
- PENDING 생성 transaction과 최종 결과 UPDATE transaction을 분리.
- 긴 작업 때문에 row lock이 오래 유지되지 않게 한다.

## UI
- PENDING: `채점 대기 중`
- 실행 중 상태를 제공한다면: `채점 중`
- 정답: 다음 보상 판단으로 이동
- 오답: 피드백 후 재풀이 가능
- 시스템 오류: 오답으로 위장하지 않고 재시도 안내
