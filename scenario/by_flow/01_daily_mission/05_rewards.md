# 05. 개별 보상 및 올클리어 보상

## 목적
채점 결과가 정답으로 확정된 뒤, 사용자가 받을 수 있는 **문제별 보상**과 **오늘의 모든 복습 문제 완료 보상**을 각각 판정하고 중복 없이 지급하는 단계다.

## 정상 흐름
1. 채점 결과가 정답으로 확정된다.
2. 서버가 해당 일일미션 문제의 개별 보상 수령 여부를 확인한다.
3. 아직 지급되지 않았다면 개별 보상을 지급한다.
4. 오늘의 모든 유효 복습 문제가 완료됐는지 다시 계산한다.
5. 모두 완료했고 올클리어 보상이 미지급이면 올클리어 보상을 지급한다.
6. 지급 결과와 최신 재화 잔액을 반환한다.

## 발생 가능한 변수

### A. 같은 문제를 여러 번 정답 처리
- **원인**: 재풀이, 제출 중복, 여러 기기 동시 제출.
- **위험**: 정답 attempt 수만큼 보상이 반복 지급될 수 있다.
- **해결**: `정답 attempt`와 `보상 지급 횟수`를 분리한다. 동일 미션·동일 문제 보상은 정책상 허용된 횟수만 지급한다.
- **DB 원칙**: 가능하면 보상 단위를 식별할 수 있는 UNIQUE/멱등 키가 필요하다. 현재 전용 스키마가 확정되지 않았다면 구현 전 결정한다.

### B. 두 요청이 동시에 보상 지급을 시도
- **원인**: 두 탭에서 거의 동시에 정답 확정, retry 요청.
- **위험**: 둘 다 `미지급`을 읽고 이중 지급.
- **해결**: 프론트 버튼 잠금으로 해결하지 않는다. 서버/DB에서 한 요청만 성공하도록 원자적 조건부 UPDATE, UNIQUE, 멱등 처리 중 스키마에 맞는 방식을 사용한다.

### C. 마지막 문제 정답과 올클리어 판정이 동시에 여러 번 실행
- **위험**: 올클리어 보상 중복 지급.
- **해결**: 올클리어 보상도 별도의 1회성 이벤트로 취급하고 DB에서 중복을 방지한다.

### D. 정답 처리 후 일부 TASK가 비활성화됨
- **질문**: 올클리어의 `전체 문제 수`를 최초 배정 기준으로 볼지, 현재 활성 문제 기준으로 볼지 결정이 필요하다.
- **정책**: 팀 결정 전 `TBD`. 구현자가 임의로 문제 수를 바꾸지 않는다.

### E. 문제 0개인 날의 올클리어
- **질문**: 0개를 `0/0 완료`로 보고 자동 보상할지, 보상 없음으로 처리할지.
- **정책**: `TBD`.

### F. 개별 보상 지급 성공 후 응답 유실
- **원인**: DB commit 후 네트워크 끊김.
- **위험**: 사용자가 다시 요청해 이중 지급.
- **해결**: 재요청 시 지급 여부를 서버에서 확인하고 이미 지급됐으면 같은 보상을 다시 차감/지급하지 않는다. 최신 상태만 반환한다.

### G. 보상 지급 도중 DB 오류
- **원칙**: 보상 지급 여부 기록과 잔액 증가는 하나의 짧은 원자적 트랜잭션으로 묶어야 한다.
- **금지**: 잔액은 증가했는데 지급 기록은 실패하거나, 반대로 지급 기록만 남는 상태.

### H. 재화 정책이 변경됨
- **원인**: 팀이 보상 수치나 재화 종류를 변경.
- **해결**: 문서/설정에서 확정된 값을 사용한다. 현재 미정 보상 액수를 이 시나리오에서 임의로 숫자로 적지 않는다.

## 개별 보상과 올클리어 보상 분리 이유
- 개별 보상: 특정 문제 성공 이벤트
- 올클리어 보상: 오늘 미션 전체 완료 이벤트

두 조건은 다르므로 같은 boolean 하나로 합치면 재시도/부분 완료/복구 때 판정이 어려워질 수 있다.

## DB/API 영향
- 보상 지급은 USERS.balance 등 실제 재화 필드를 변경한다.
- 지급 조건과 지급 여부를 서버가 확인해야 한다.
- 현재 ERD에 일일미션 보상 전용 테이블이 없다면 필요한 스키마 변경 여부를 별도로 결정한다.
- 최종 보상 액수는 `TBD`.

## 트랜잭션/락 원칙
- 보상 판정과 잔액 반영은 짧게 끝낸다.
- Docker 채점 작업과 같은 트랜잭션으로 묶지 않는다.
- 명시적 `FOR UPDATE`는 단순히 불안하다는 이유로 추가하지 않고, 원자적 UPDATE/UNIQUE로 해결 가능한지 우선 검토한다.

## UI
- 개별 보상 성공: `문제 완료! 보상을 획득했습니다.`
- 이미 받은 보상: 중복 지급 없이 `이미 받은 보상입니다.` 또는 단순 완료 상태
- 올클리어: 별도 강조 화면/배지 가능
- 지급 실패: 잔액을 임의로 화면에서 올리지 말고 서버 재조회
