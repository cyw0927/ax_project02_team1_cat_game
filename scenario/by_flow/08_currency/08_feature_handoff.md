# 08. 상점·가챠·하우징 연결

## 목적
재화 획득과 사용 결과를 다음 기능으로 자연스럽게 연결하고, 각 화면이 최신 서버 상태를 기준으로 동작하게 한다.

## 정상 흐름
### 상점
`재화 획득 → 최신 balance 확인 → 상점 → 서버 가격/잔액 검증 → 원자 차감 → INVENTORIES 반영 → 하우징`

### 가챠
`재화 획득 → 최신 재화 확인 → 가챠 → 서버 비용/정책 검증 → 차감/결과 확정 → USER_CATS 등 보유 상태 반영 → 하우징`

### 하우징
하우징은 재화를 직접 소비하는 곳이라기보다 상점과 가챠 결과가 누적되어 보이는 공간이다. 진입 시 최신 INVENTORIES, USER_CATS, PLACED_OBJECTS를 다시 확인한다.

## 발생 가능한 변수
### A. 보상 직후 상점 진입
- 보상 응답은 받았지만 화면 balance가 갱신되지 않았을 수 있다.
- 서버 거래 검증을 통과하면 실제 구매는 가능해야 한다.

### B. 상점 구매 직후 하우징에서 아이템이 안 보임
- 오래된 inventory 캐시 가능.
- 하우징 진입 시 서버 inventory 재조회.

### C. 가챠 직후 하우징에서 고양이가 안 보임
- USER_CATS 최신 상태를 재조회한다.
- 가챠 결과 화면의 임시 데이터만으로 영구 소유를 판단하지 않는다.

### D. 다른 기기에서 동시에 재화 사용
- 다음 거래는 항상 서버 최신 잔액으로 판단한다.

### E. balance와 mileage 역할 혼동
- 현재 USERS에 두 필드가 있지만 최종 경제 구조는 확정되지 않았다.
- 상점/가챠별 사용 통화를 임의로 하드코딩하지 않는다.

## 공통 서버 원칙
- DB가 권위 상태.
- 중요한 거래 전 서버 재검증.
- 원자 증감 우선.
- 중복 지급/사용은 멱등성으로 보호.
- 장시간 외부 작업 중 transaction 유지 금지.

## UI
- 홈의 잔액, 상점 잔액, 가챠 잔액이 서로 다르면 서버 최신값으로 갱신한다.
- 구매/뽑기 성공 후 최신 잔액과 획득 결과를 함께 표시한다.
- 하우징에서는 보유 자산을 서버에서 다시 로드한다.

## 전체 재화 흐름 종료
`일일 미션 / 학습 / 배틀 / 승급전 / 출석 → 재화 획득 → 상점 또는 가챠 → 가구/고양이 획득 → 하우징`

## 테스트
- 학습 보상 직후 상점 구매
- 배틀 보상 직후 가챠 이동
- 상점 구매 직후 하우징
- 가챠 직후 하우징
- 다른 기기 동시 사용
- 오래된 홈 balance
- balance/mileage 정책 미확정 상태에서 임의 사용처 하드코딩 여부
