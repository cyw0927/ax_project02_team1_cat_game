# 05. 재화 사용 요청

## 목적
상점 구매나 가챠처럼 재화를 소비하는 요청이 들어왔을 때, 클라이언트 화면 값이 아니라 서버의 최신 가격·비용·잔액을 기준으로 거래를 시작한다.

## 정상 흐름
1. 사용자가 상점 구매 또는 가챠 요청을 보낸다.
2. 서버가 대상 기능의 최신 가격/비용 정책을 조회한다.
3. 사용자 최신 잔액을 기준으로 사용 가능 여부를 판단한다.
4. 실제 차감은 다음 단계의 원자 차감에서 수행한다.

## 발생 가능한 변수
### A. 화면에 표시된 가격이 오래됨
- 원인: 관리자가 가격 변경, 오래 열린 탭.
- 해결: 서버 가격을 권위값으로 사용한다. 필요하면 변경된 가격을 응답에 포함한다.

### B. 프론트에서 잔액 충분 표시였지만 실제로는 부족
- 원인: 다른 탭/기기에서 이미 사용.
- 해결: 프론트 검사만으로 거래 확정하지 않고 서버에서 재검증한다.

### C. 가챠 비용 정책 미확정
- 비용, 사용 재화 종류, 1회/다회 뽑기 가격은 `TBD`.
- 임의 숫자를 코드/문서에 확정하지 않는다.

### D. 비정상 수량/아이템/요청값 조작
- 서버가 item_id, quantity, draw_count 등 허용 범위를 검증한다.

## DB/API 영향
- 상점은 ITEMS.price와 USERS.balance 등 확인.
- 가챠는 최종 비용 정책 및 재화 필드 확정 필요.
- 실제 차감은 아직 commit하지 않는다.

## UI
- `구매 가능` 표시와 실제 성공은 구분한다.
- 서버 재검증 실패 시 최신 가격/잔액으로 화면을 갱신한다.
