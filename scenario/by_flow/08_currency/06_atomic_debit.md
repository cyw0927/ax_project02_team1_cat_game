# 06. 재화 원자 차감

## 목적
상점/가챠 사용 시 잔액이 음수가 되지 않도록 서버 DB에서 조건부 원자 차감을 수행한다.

## 정상 흐름
1. 서버가 최신 비용을 확정한다.
2. 조건부 UPDATE로 잔액을 차감한다.
3. 영향 row가 1이면 차감 성공으로 다음 처리 진행.
4. 영향 row가 0이면 잔액 부족 또는 사용자 상태 이상으로 거래를 중단한다.

## 권장 형태
```sql
UPDATE users
SET balance = balance - :cost
WHERE id = :user_id
  AND balance >= :cost;
```

## 발생 가능한 변수
### A. 두 기기에서 동시에 구매
- 두 요청 모두 화면상 충분해 보여도 DB 조건부 UPDATE 결과에 따라 실제 성공 수가 결정된다.
- 잔액 음수는 발생하지 않아야 한다.

### B. 상점 inventory 증가 실패
- 차감과 inventory 반영은 같은 짧은 transaction으로 묶어 전체 rollback한다.

### C. 가챠 결과 생성 실패
- 가챠의 비용 차감, 결과 생성, 보유 반영을 어디까지 한 transaction/멱등 단위로 묶을지는 최종 API/이력 설계와 함께 확정해야 한다.
- 비용만 차감되고 결과가 유실되는 상태는 피해야 한다.

### D. 불필요한 row lock
- 단순 잔액 차감만을 위해 장시간 `SELECT ... FOR UPDATE`를 유지하지 않는다.
- 조건부 UPDATE를 우선한다.

## DB/락 원칙
- transaction은 짧게.
- 외부 작업과 함께 열어두지 않는다.
- 단순 증감은 DB 원자 연산 사용.

## UI
- 차감 성공 후 서버 최신 잔액 표시.
- 잔액 부족이면 `재화가 부족합니다`와 최신 잔액을 표시.
- 프론트에서 먼저 잔액을 영구 차감한 것처럼 확정하지 않는다.
