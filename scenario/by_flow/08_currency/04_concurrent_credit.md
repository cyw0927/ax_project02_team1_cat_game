# 04. 동시 획득 및 잔액 동기화

## 목적
여러 기능에서 거의 동시에 재화가 들어오거나 여러 기기에서 같은 사용자의 화면을 보고 있어도 서버 잔액을 권위값으로 유지한다.

## 정상 흐름
1. 각 보상은 독립적으로 멱등성을 확인한다.
2. 각 보상 transaction은 짧게 원자 증가를 수행한다.
3. 완료 순서와 관계없이 최종 DB 잔액에 모든 유효 보상이 반영된다.
4. 클라이언트는 응답 또는 재조회 결과로 최신 잔액을 표시한다.

## 발생 가능한 변수
### A. 응답 순서가 실제 commit 순서와 다름
- 먼저 발생한 요청의 응답이 나중에 도착할 수 있다.
- 해결: 오래된 응답 하나만 믿고 잔액을 되돌리지 않는다. 필요하면 거래 후 profile/balance를 재조회한다.

### B. PC와 모바일에서 동시에 접속
- 한쪽은 보상을 받고 다른 쪽은 상점/가챠를 사용할 수 있다.
- 해결: 다음 거래마다 서버가 최신 잔액으로 검증한다.

### C. 오래 열린 화면
- 화면 숫자는 stale 상태가 될 수 있다.
- 해결: 중요한 화면 진입 또는 거래 직전에 서버 상태를 다시 읽는다.

### D. 여러 Background 보상 완료
- 채점 완료 순서가 제출 순서와 다를 수 있다.
- 해결: 보상 식별 단위가 서로 다르면 각각 독립적으로 반영하며 UI 순서와 DB 권위 상태를 분리한다.

## DB/API 영향
- USERS.balance가 권위 상태.
- 각 보상 원천은 자체 결과 상태를 가진다.
- 범용 거래 이력이 없다면 장애 추적 한계가 있으므로 ledger 여부는 `TBD`.

## UI
- 다른 화면에서 잔액이 변할 수 있다는 전제.
- 거래 완료 후 서버 반환 잔액으로 갱신.
- 필요 시 재조회 버튼/자동 새로고침 정책 검토.
